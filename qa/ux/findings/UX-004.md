## Problem

I created profile "אורחים" as "עותק של רגיל" from **פרופילים**. The dialog closed with "נשמר" and nothing
else changed: the timers list is titled "טיימרים · רגיל" and shows only the active profile's rules
(`view.rules.filter((r) => r.profile === view.active_profile)`). There is no way to open "אורחים" to adjust
its timers except switching the **פרופיל** select, which is the live control that decides what will switch
on and off this Shabbat. The preview also only reflects the active profile.

The profiles dialog lists names only: no rename, no delete, no timer count.

## Why it matters

Editing the guests profile on a Thursday means the house runs the guests timers this Shabbat unless the admin
remembers to switch back. A setting that controls a hot plate over Shabbat should not require changing live
state to inspect.

## Evidence

![list shows only the active profile's timers](https://github.com/bareli/good_days/blob/main/qa/evidence/UX-004-rules-of-active-profile-only.png?raw=1)

After adding "אורחים" the view is unchanged; the list header says "טיימרים · רגיל".

## Recommendation

Proposal for the owner: separate "which profile is active" from "which profile am I looking at".
A segmented control or tabs above the timers list ("רגיל | אורחים") chooses the profile being viewed and
edited; the active one carries a badge "פעיל בשבת הקרובה". The preview gets its own line: "תצוגה מקדימה לפי
פרופיל: רגיל". Add rename / delete and a timer count in the profiles dialog.

## Kind

Works, could be better.

## Prototype

Offered in the report (timers tab: profile view, skip state, non-admin notice).
