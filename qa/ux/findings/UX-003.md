## Problem

The field "שנה עברית (רשות)" is `<input type=number min=3000 max=6500>` with the hint "מציג גיל או מספר שנים,
למשל 5745." Israelis write and read the Hebrew year in letters (תש״ע, תשמ״ה); almost nobody knows it as 5770.
Typing "תש״ע" into the field produces nothing (the browser discards non-digits), no error is shown, and
**שמירה** succeeds with no year. The saved yahrzeit then shows no count ("יום השנה: סבא משה" instead of
"(17)") and the user is not told why.

## Why it matters

The yahrzeit and anniversary counts are a visible feature (titles, reminders). The dominant input path for a
yahrzeit is a gematria date copied from a stone or a card. The failure is silent, so the user believes the
year was stored.

## Evidence

![saved with no year count](https://github.com/bareli/good_days/blob/main/qa/evidence/UX-003-saved-without-year.png?raw=1)

Steps: name "סבא משה", סוג יום השנה, יום ל׳, חודש חשוון, click the year field, type `תש״ע`, שמירה. Result:
saved, list shows "יום השנה: סבא משה" with no number. Entering 5770 afterwards shows "(17)".

## Recommendation

Proposal for the owner:

1. Accept both forms: a text input that parses gematria (תש״ע, תשע, ה׳תש״ע) and digits (5770), echoing the
   parsed value next to it ("= 5770", or "תש״ע" when digits were typed).
2. Hint text: "למשל תשמ״ה או 5745. מציג גיל או מספר שנים."
3. If the value cannot be parsed, show the existing inline error instead of dropping it.

## Kind

Works, could be better (the digits path works; the natural path fails silently).

## Prototype

Not offered separately; a small field change.
