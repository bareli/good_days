## Problem

In an otherwise Hebrew form:

- "שעת תזכורת" is a TimeSelector with three required fields **hh\* mm\* ss\*** (seconds, English placeholders).
  The code keeps only HH:MM.
- The minute fields show the unit **"min"**, and "מספר ימים לחישוב מראש" shows **"d"**
  (`unit_of_measurement="min"` / `"d"` in `config_flow.py`).
- The notify help text reads "שירותי התראה, למשל mobile_app_my_phone. ... ריק: רק האירוע good_days_reminder." A
  household admin sees an event name, not an outcome.

The rest of the Hebrew is clear: location, diaspora ("כבוי בארץ ישראל. מופעל בחוץ לארץ."), candle-lighting
minutes with city examples, and the category list read well.

## Why it matters

Small, but each one tells a Hebrew user the screen was not written for them, and the seconds field is noise
on a setting people touch once.

## Evidence

![options form, lower half](https://github.com/bareli/good_days/blob/main/qa/evidence/UX-011-options-units-seconds.png?raw=1)

## Recommendation

Proposal for the owner:

- Reminder time: `TimeSelector({"no_second": True})` (supported by HA's time selector).
- Units: translate through the strings file or drop the unit and put it in the label ("דקות", "ימים").
- Notify help (he): "לאן לשלוח תזכורות (למשל הטלפון שלך). בטלפון יופיעו הכפתורים הבנתי / תזכירו לי מחר. בלי
  יעד: אין התראה, אבל אוטומציות יכולות להגיב לאירוע good_days_reminder."
