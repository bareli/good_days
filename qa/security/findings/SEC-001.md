## Summary

`good_days/timers/settings` is admin-only (`@websocket_api.require_admin`) and the README says
"Everyone sees the timers; only admins can change them". The same three settings are also exposed
as entities, `switch.good_days_shabbat_timers`, `switch.good_days_skip_next_shabbat_or_chag` and
`select.good_days_timer_profile`, whose handlers call the same `async_apply_settings()` with no
check of who is calling. Any logged-in household member can therefore turn every timer off, skip the
coming Shabbat / Chag, or move the house to another profile, with ordinary `switch.turn_off` /
`select.select_option` service calls (the HA UI more-info dialog is enough, no tooling needed).

## Steps to reproduce

Identity: `qa_user` (non-admin, `is_admin: false`, token from the login flow). As admin beforehand:
hot-plate preset created, second profile `SECguests` added. State before: timers `enabled: true`,
`skip_next: false`, `active_profile: default`.

1. As `qa_user`, the admin-only WS path is refused (control):
   `{"type":"good_days/timers/settings","enabled":false}` -> `{"success":false,"error":{"code":"unauthorized"}}`
   (same for `skip_next`, `active_profile`, and every other `timers/*` write, `ics/get`, `ics/set`).
2. As `qa_user`, over the same WS connection:
   ```
   {"type":"call_service","domain":"switch","service":"turn_off","target":{"entity_id":"switch.good_days_shabbat_timers"}}
   {"type":"call_service","domain":"switch","service":"turn_on","target":{"entity_id":"switch.good_days_skip_next_shabbat_or_chag"}}
   {"type":"call_service","domain":"select","service":"select_option","target":{"entity_id":"select.good_days_timer_profile"},"service_data":{"option":"SECguests"}}
   ```
3. As admin, `{"type":"good_days/timers/get"}`.

## Expected

Source of the expectation: `qa/PROJECT.md` *Always in scope* ("every `good_days/timers/*` write
require admin"), README "only admins can change them", and the WS command's own `require_admin`.
The entity path should refuse a non-admin the same way, or the owner should rule that some of these
(e.g. "skip next") are meant for every family member and the README should say so.

## Actual

All three calls succeed as the non-admin user:
```
{"id":1,"type":"result","success":true,"result":{"context":{"id":"01M3SZ226D...","user_id":"98f996626957476aa00ed84e4b022290"}}}
{"id":2,"type":"result","success":true,"result":{"context":{"id":"01M3SZ226R...","user_id":"98f996626957476aa00ed84e4b022290"}}}
{"id":3,"type":"result","success":true,"result":{"context":{"id":"01M3SZ2274...","user_id":"98f996626957476aa00ed84e4b022290"}}}
```
Admin `timers/get` afterwards: `"enabled": false, "active_profile": "SECguests", "skip_next": true`,
persisted in `.storage/good_days.timers.<entry_id>`. The `user_id` is `qa_user`'s.

## Evidence

The request/response pairs above (tokens not shown; nothing secret in them). The panel as `qa_user`
afterwards shows the timers off, the coming Shemini Atzeret skipped and profile `SECguests` active.

## Impact in this product's threat model

A household HA: the admin configures the Shabbat house, family members (kids, guests with an HA
login) are non-admin. Any of them can silently turn off the hot plate / urn / light schedule for the
coming Shabbat or Chag (or swap to a profile with other devices), and on Shabbat itself the observant
household cannot turn it back on. Limiting factor, and the reason this is MEDIUM rather than HIGH:
in Home Assistant's permission model a non-admin can already switch the target devices themselves
(e.g. `input_boolean.hot_plate`), so no device becomes reachable that was not; what crosses the
boundary is the *configuration* the admin set, and it persists.

## Likely root cause

`switch.py` `TimersSwitch` / `SkipNextSwitch` and `select.py` `TimerProfileSelect` call
`websocket_timers.async_apply_settings()` directly; the admin check lives only on the WS decorator.
Proven by the reproduction above.

## Relevant files

- `custom_components/good_days/switch.py` (`async_turn_on/off`)
- `custom_components/good_days/select.py` (`async_select_option`)
- `custom_components/good_days/websocket_timers.py` (`ws_settings` has `require_admin`, `async_apply_settings` has none)

## Recommended remediation

Owner decision first (hence `model:opus`): which of the three are family controls and which are
admin configuration. For the admin ones, check the caller in the entity handler, e.g. look up
`self._context.user_id` / `hass.auth.async_get_user()` and raise `homeassistant.exceptions.Unauthorized`
when the user exists and is not admin (a `None` user = automation / system call, keep allowed).
Update the README sentence to match whatever is ruled.

## Regression test

Plan IDs SEC-001 / TMR-007. A pytest that calls `switch.turn_off` on
`switch.good_days_shabbat_timers` with a non-admin user's `Context` and asserts `Unauthorized` and
`store.enabled` unchanged (and the same for the select), plus the admin and no-user cases still
working.
