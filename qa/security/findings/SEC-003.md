## Summary

The shared `_int()` helpers (`storage._int`, `timers._int`) do `float(value)` inside a `try`, then
`int(number)` outside it. `float("nan")`, `float("inf")` and `float("1e400")` succeed, and `int()` of
them raises `ValueError` / `OverflowError`, which nothing catches. The WS command fails with a
generic `unknown_error` and a full traceback is written to the HA log at ERROR level. Reachable by
any logged-in user through `good_days/dates/add` / `dates/update` (open by design).

## Steps to reproduce

Identity `qa_user` (non-admin):
```
{"type":"good_days/dates/add","name":"SEC nan","kind":"birthday","hebrew_day":"nan","hebrew_month":"tishrei"}
{"type":"good_days/dates/add","name":"SEC inf","kind":"birthday","hebrew_day":"1","original_year":"inf","hebrew_month":"tishrei"}
{"type":"good_days/dates/add","name":"SEC rd","kind":"birthday","hebrew_day":1,"hebrew_month":"tishrei","reminder_days":["nan"]}
{"type":"good_days/dates/add","name":"SEC float","kind":"birthday","hebrew_day":"1e400","hebrew_month":"tishrei"}
```
Identity `qa_admin`:
```
{"type":"good_days/timers/save","action":"on","anchor":"candle_lighting","offset_min":"nan","applies_to":["shabbat"],"name":"SEC nan","targets":["input_boolean.guests"]}
{"type":"good_days/timers/save", ... "offset_min":"inf" ...}
```

## Expected

`{"errors": {"hebrew_day": "invalid_day"}}` (etc.), exactly as for `"hebrew_day":"{{ 7*7 }}"`, which
returns `invalid_day` correctly. Source: plan WS-001 "Every WS command validates input and returns
errors, not exceptions"; PROJECT.md *Fix constraints*.

## Actual

Every one of the six returns `{"success": false, "error": {"code": "unknown_error", "message": "Unknown error"}}`.
HA log (paths shortened):
```
ERROR ... Error handling message: Unknown error (unknown_error) QA User from 127.0.0.1
  File ".../good_days/storage.py", in _int
    return int(number) if number == int(number) else None
ValueError: cannot convert float NaN to integer
...
OverflowError: cannot convert float infinity to integer
```
Nothing is persisted (checked with `dates/list`), so there is no data corruption.

## Impact in this product's threat model

Low. A non-admin can make the integration throw and fill the HA log with ERROR tracebacks
(one per request, no rate limit beyond the WS connection), and the panel shows a generic failure
instead of the inline field message. No data crosses a boundary and nothing is stored. The services
path is not affected (`vol.Coerce(int)` rejects `"nan"` as `vol.Invalid`).

## Relevant files

- `custom_components/good_days/storage.py` (`_int`)
- `custom_components/good_days/timers.py` (`_int`)

## Recommended remediation

Move the `int()` into the `try` and catch `(TypeError, ValueError, OverflowError)`, or reject
non-finite values with `math.isfinite(number)` before converting. One helper would serve both files.

## Regression test

WS-001. Parametrised pytest over `validate_date` / `validate_rule` with `"nan"`, `"inf"`, `"-inf"`,
`"1e400"` for each numeric field, asserting a field error code and no exception.
