## Summary

WCAG 2.1 AA 1.4.3 Contrast (Minimum). With Home Assistant's default theme `--primary-color` is rgb(0,154,199). Good Days uses it
as **text colour** on white (selected tab, "Edit", "Run now", "Duplicate", "Cancel", "Profiles", "From a preset") and as a
**background under white text** (primary buttons "Add date", "Save", "Add timer"; the "Now" chip in card and panel). All measure **3.26:1**
at 10.9-14 px regular weight; 4.5:1 is needed. The selected tab is 3.12:1 on the page background. The destructive "Delete" text and the inline
error messages use `--error-color` rgb(219,68,55): **4.29:1** light (3.97:1 dark for "Delete") at 11-14 px. Dark theme: primary text passes
(5.23:1) but the primary button and chip fill with white text still fails (3.26:1). Ordinary body and secondary text pass (6.48:1 or better).

The cause is a design choice (theme colour as text) on a theme whose accent does not reach 4.5:1, which is Home Assistant's own default.
Users of other themes will see other ratios; the defect is the dependency with no safeguard. It is a product / design call, hence model opus.

## Steps to reproduce

1. Panel "ימים טובים", light theme, he, `qa_admin`, dates tab with rows. Run `gd-F.mjs he-IL light` (computed colour against effective background).
2. Open "Add timer" and submit it empty (`gd-G.mjs`): the inline error `.err` is 4.29:1.

## Expected

4.5:1 for normal text (1.4.3). Component boundaries need 3:1 (1.4.11); those pass.

## Actual

```
tab selected         3.12  rgb(0,154,199) on rgb(250,250,250)  14px 500
primary btn          3.26  white on rgb(0,154,199)             14px
Edit / Run / Cancel  3.26  rgb(0,154,199) on white             14px
chip.now             3.26  white on rgb(0,154,199)             10.9px  (card and panel)
Delete btn           4.29  rgb(219,68,55) on white             14px    (dark: 3.97)
inline error .err    4.29  rgb(219,68,55) on white             11.2px
```

## Evidence

Computed-style measurement in Chromium 153, both themes. Dark excerpts: primary text 5.23, selected tab 5.80, primary fill 3.26, delete 3.97.

## Likely root cause

Likely: colours taken straight from theme variables with no contrast floor.

## Relevant files

`custom_components/good_days/www/panel.js` STYLE (`button.primary`, `button.text`, `.tab[aria-selected=true]`, `.chip.now`, `button.danger`, `.err`, `.status.error`),
`custom_components/good_days/www/card.js` STYLE (`.chip.now`).

## Recommended remediation

Owner's call: darken the text use (`color-mix(in srgb, var(--primary-color) 70%, black)`, and dark text on light primary fills when the ratio is low),
or keep the brand colours and document the deviation. Re-measure in both themes; target 4.5:1 for all text above.

## Regression test

A11Y-001. Theme-dependent, so a browser measurement; nothing a unit test can hold.
