## Summary

WCAG 2.1 A/AA: 1.3.1 Info and Relationships, 2.5.3 Label in Name, 3.3.1 Error Identification, 4.1.2 Name, Role, Value.
In the add/edit timer dialog and the preset dialog, the visible label "מכשירים" / "Devices" is a `<label for="t-targets">`
pointing at an `<ha-selector>` host element. A label cannot name a custom element, so the real focusable control
(inside Home Assistant's entity picker) is announced with HA's own generic text "בחירת ישות *" ("Choose entity"), not "Devices".
The hint (`aria-describedby`) and the inline error are attached to the non-focusable host, so they are never associated with the
control the keyboard user is standing on. On a validation error `first.focus()` is called on the `ha-selector` host, which is not focusable,
so focus stays where the user pressed Enter. The error does appear in an `aria-live` span, which is the only channel.

The picker itself is Home Assistant's component; the missing name, association and focus target are ours (we set no `label` on it).

## Steps to reproduce

1. Panel "ימים טובים", tab "טיימרים לשבת" (language he), as `qa_admin`. Focus "הוספת טיימר", Enter.
2. Type a name, leave Devices empty. Tab once: focus is on the picker's inner button; the accessibility tree shows `listitem: בחירת ישות *` (no "מכשירים").
3. Shift+Tab to the name field, press Enter (submit). Error "יש לבחור לפחות מכשיר אחד." appears under the picker; focus stays on the name field; `ha-selector[aria-invalid=true]` is set on the non-focusable host.
4. The same happens in "מתבנית" (preset). For the "Only if (optional)" conditions picker the focusable control is an icon-only "+" button whose accessibility-tree entry has no name (Home Assistant's own component; we pass no label to it either).

## Expected

Label text programmatically in the control's name (2.5.3, 4.1.2); error tied to the control, focus moved to the first invalid control
like the other fields in the same dialog (3.3.1). The code already does this for every native field (`aria-describedby`, `aria-invalid`, focus).

## Actual

See Summary. Measured in Chromium 153 with Playwright 1.63 accessibility snapshots (`gd-G.mjs`, `gd-H.mjs`). No screen reader was run;
the name and structure are from the browser's accessibility tree.

## Likely root cause

Likely: `_targetsControl()` sets no `label` / `helper` on `ha-selector`, and `_field()` assumes every control is labelable and focusable.
Would be proven by setting `picker.label` and re-reading the accessibility tree.

## Relevant files

`custom_components/good_days/www/panel.js`: `_targetsControl()` (~1549), `_field()` (~1507), `_showFieldErrors()` (~1531), conditions `ha-selector` (~1649).

## Recommended remediation

Set `picker.label = <the field label>` (and `helper`) on the `ha-selector`s, or use `aria-label` on the inner control through HA's API; in
`_showFieldErrors` focus the picker's inner control (e.g. `picker.focus()` when HA exposes it, else the first focusable descendant in its shadow tree) and keep
the live error. Re-read the accessibility tree afterwards.

## Regression test

A11Y-001. A unit test can only pin that `label` is set on the selector; it cannot see the accessibility tree.
