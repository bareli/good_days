## Summary

WCAG 2.1 AA 1.4.10 Reflow (and 1.4.4 Resize Text): at 320 CSS px, and at 640 px (1280 px at 200% zoom), the compact
card's single line is cut with an ellipsis. The part that is lost is the part the card exists to show: the rest of the
holiday name, "מחר", and the candle-lighting time. The full text is only in a `title` attribute, which a mouse
user can reach by hovering. A keyboard user can't reach it, and neither can a touch user on a phone, which is exactly
where 320 px applies. Activating the row opens Home Assistant's more-info for `calendar.good_days_holidays`, and that
dialog shows only "חגים / מופעל", not the missing text. Screen-reader users are not affected (the DOM holds the full
text). This is what was left over after #19: #19 fixed the full card and the panel, and its record allowed the compact
variant to stay ellipsised with a `title`. Verifying #19 showed that a `title` doesn't make the text available.

## Steps to reproduce

1. Dashboard with `type: custom:good-days-card`, `compact: true` (dev: `/gd-qa/qa`, second card), user `qa_admin`, he, light, Chromium.
2. Set the viewport to 320 x 568. Scroll to the compact card.
3. The line reads "חול המועד סוכות · הבא: שמיני עצרת · שמחת ת…". Measure `.name`: scrollWidth 437 > clientWidth 252, `white-space: nowrap`, `text-overflow: ellipsis`.
4. Focus the row (it is a `button.compact`) and press Enter. The more-info dialog opens with "חגים", "מופעל" and a timestamp, but not the missing text.
5. At 640 x 900 (200% zoom of 1280) the same line is cut: 437 > 256.

## Expected

All content is available at 320 CSS px without two-dimensional scrolling, and not only through hover (WCAG 2.1 AA 1.4.10;
1.4.4 at 200%). The expectation comes from the declared standard (`qa/PROJECT.md`, *Accessibility*: WCAG 2.1 AA).

## Actual

```
320 px: .name scrollWidth 437 > clientWidth 252, nowrap + ellipsis
        visible: "חול המועד סוכות · הבא: שמיני עצרת · שמחת ת…"
        full   : "חול המועד סוכות · הבא: שמיני עצרת · שמחת תורה · שבת · מחר · הדלקת נרות 17:54"  (title only)
640 px: .name scrollWidth 437 > clientWidth 256
Enter on the row -> ha-more-info-dialog for calendar.good_days_holidays: "Good Days | חגים | ... | מופעל" (no event text)
```

## Likely root cause

Proven by the CSS: `button.compact .name { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }`, and the full text
only in `name.title` (`_renderCompact`). The design intends "one line" (option label "תצוגה מקוצרת (שורה אחת)").

## Relevant files

`custom_components/good_days/www/card.js`: STYLE `button.compact .name` (~line 219), `_compactLine()` (~820), `_renderCompact()` (~842).

## Recommended remediation

This is a design call ("one line" is the feature's promise), hence model opus. Options:
- Let the line wrap when it doesn't fit (`white-space: normal; overflow-wrap: anywhere`), which is the simplest way to conform.
- Or keep one line but make the full text available without hover. For example, Enter / tap expands the row in place (like
  `button.item` details) instead of, or before, opening more-info.
- Or shorten the line by priority as the width shrinks (drop "חול המועד סוכות" before the next item's name and time). This
  alone is fragile with long Hebrew titles.
