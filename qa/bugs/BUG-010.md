## Summary

With two Good Days entries (SPEC §7.2, for example home plus parents abroad), a card bound to entry 1 that lists
entry 2's `calendar.good_days_family_2` under `calendars` never shows that calendar's events, and nothing tells the
user why: the calendar is neither merged nor reported in `errors`. The card's visual editor offers that calendar in
its "Calendars to merge" picker.

## Steps to reproduce

1. Two entries: E1 Israel (`01M3SYSGV9WAGVWVRGYS184NVJ`) and E2 New York, diaspora (`01M3SZ15M13669025785K7A1CP`).
2. Add to E2 a birthday "Grandpa Sam", 25 Tishrei (occurs 2026-10-06).
3. WS: `{"type":"good_days/upcoming","entry_id":"<E1>","days":30,"limit":20,"calendars":["calendar.good_days_family_2","calendar.missing"],"categories":["family","yom_tov"]}`

## Expected

Grandpa Sam's birthday (6 Oct) merged, or at least `calendar.good_days_family_2` reported in `errors`. Sources:
SPEC §6.3 (`calendars`: "external calendars to merge"); the code comment states the intent is only to avoid listing
the card's own calendars twice ("Our own calendars are already merged above; never list them twice"). That another
entry's calendar counts as external is my inference; the owner may rule otherwise.

## Actual

Items contain only E1's family dates and holidays. `errors` lists only `calendar.missing`. The event exists:
`calendar.get_events` on `calendar.good_days_family_2` returns
`2026-10-06 -> 2026-10-07 | Grandpa Sam's birthday | 25 Tishrei 5787`.

## Evidence

```
2026-10-01 family יום הולדת 37 לדני
2026-10-02T17:54:00+03:00 holidays שמיני עצרת · שמחת תורה · שבת
2026-10-02T18:24:00+03:00 family יום השנה: סבא משה (17)
2026-10-03T18:23:00+03:00 family יום השנה: סבתא רחל (7)
errors [{'entity_id': 'calendar.missing', 'error': 'Service call requested response data but did not match any entities'}]
```

Nothing visible to capture beyond a missing row; the WS output above is the evidence.

## Likely root cause

`ws_upcoming` (websocket.py) skips every calendar whose registry `platform == DOMAIN`, not only those of the resolved
entry. Likely; comparing `reg.config_entry_id` with `runtime.entry.entry_id` would prove it.

## Relevant files

- `custom_components/good_days/websocket.py` (`ws_upcoming`, the "never list them twice" block)

## Recommended remediation

Drop only calendars belonging to the resolved entry; fetch other entries' calendars like any external calendar (or
list them in `errors` if the owner rules they are unsupported).
